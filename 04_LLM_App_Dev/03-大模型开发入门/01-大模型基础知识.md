## 一、大模型是什么

大语言模型简称大模型（英文 Large Language Model，缩写 LLM），旨在理解和生成人类语言。大模型的“大”主要体现在：

* 参数量大：参数量越大通常模型越强，就好像一个学生的脑容量和理解能力
* 训练数据量大：训练数据量越大通常模型越强，就好像一个学生读过的书、做过的题、见过的案例
* 训练算力大：大模型训练不是普通电脑能完成的，通常需要大量时间、大量 GPU/TPU 集群，训练成本很高，就好像一个学生的学习时间和训练强度
* 能力覆盖范围大：传统 NLP 模型往往是单任务模型，比如只做翻译、只做摘要等，而大模型则可以同时处理很多类型的自然语言任务，比如问答（比如你问一个问题它给答案）、对话（比如像聊天一样连续多轮交流）、翻译（比如把英文翻译成中文）、文本分类（比如区分一段评论是好评还是差评）、写作（比如让它给我们写文案）、总结（比如让它给我们总结会议摘要）、代码生成（比如让它给我们写代码）等

但严格来说，大模型 ≠ 大语言模型，大模型是一个更大的概念，而大语言模型则主要指处理自然语言文本的模型，大模型包含大语言模型，大模型还包含图片模型、语音模型、视频模型、多模态模型等。之所以有此简称是因为现在大多数“大模型应用开发”的课程、岗位、项目，核心都还是围绕 LLM 调用、Prompt、RAG、Agent、Function Calling、工作流编排、模型接口集成等能力来做应用，比如聊天助手、知识库问答、Agent、工作流自动化、代码助手、数据分析助手等。

## 二、大模型主流架构

```
             Transformer 架构家族
                    │
     ┌──────────────┼──────────────┐
     │              │              │
Encoder-only   Encoder-Decoder  Decoder-only
（理解型架构）   （理解+生成型架构） （生成型架构）
     │              │              │
BERT/ELECTRA     T5/BART        GPT/DeepSeel
```

#### Transformer 架构家族

**Transformer** 是 Google 在 2017 年论文《Attention Is All You Need》中提出的一种**神经网络架构**，它规定了一套神经网络应该怎么搭：

```
 Input
   │
Encoder ×N（N = Encoder 的层数）
   │
Encoder 输出
   │
Decoder ×N（N = Decoder 的层数）
   │
Output
```

Transformer 架构虽然很好，**编码器擅长理解，解码器擅长生成，**但不同任务需要不同结构，于是大家开始“裁剪” Transformer 架构，从而演变出了 Encoder-only  Transformer 架构、Encoder-Decoder Transformer 架构、Decoder-only Transformer 架构。称呼上也发生了一些变化，Transformer 架构不再代表某个具体的架构、而是代表一个架构家族，Encoder-only、Encoder-Decoder、Decoder-only 才代表该架构家族里某个具体的架构。

#### 第一种：Encoder-only 编码器架构

只保留 Encoder，去掉 Decoder

```
 Input
   │
Encoder ×N（N = Encoder 的层数）
   │
Encoder 输出
   │
Output
```

这种架构**只负责理解输入内容，不负责推理生成内容**，典型应用：文本分类、RAG 中 Embedding 等。例如：

```
"今天很开心"
↓
Encoder ×N（N = Encoder 的层数）
↓
Encoder 输出
↓
判断：Positive
```

优点是：

* 理解能力强
* 训练效率高

缺点是：

* 不能生成内容

代表模型：

* BERT
* ELECTRA

#### 第二种：Encoder-Decoder 编码器-解码器架构

既保留 Encoder，也保留 Decoder，这其实就是原始的 Transformer 架构

```
 Input
   │
Encoder ×N（N = Encoder 的层数）
   │
Encoder 输出
   │
Decoder ×N（N = Decoder 的层数）
   │
Output
```

这种架构**既负责理解输入内容，也负责推理生成内容**，典型应用：翻译、摘要等。例如：

```
"Translate: Hello"
↓
Encoder ×N（N = Encoder 的层数）
↓
Encoder 输出
↓
Decoder ×N（N = Decoder 的层数）
↓
"你好"
```

优点是：

* 理解能力强
* 也能生成内容

缺点是：

* 推理速度较慢，因为需要同时运行 Encoder 和 Decoder

代表模型：

* T5
* BART

#### 第三种：Decoder-only 解码器架构（目前最主流）

只保留 Decoder，去掉 Encoder

```
 Input
   │
Decoder ×N（N = Decoder 的层数）
   │
Output
```

这种架构**只负责推理生成内容，不负责理解输入内容（注意：现在大模型能很好地跟我们聊天，不是因为它们充分理解了我们的输入才回答地好，它们压根没做理解这件事，而是直接拿着输入去推理接下来的一个 token 该生成什么内容，之所以回答地好，是因为大模型的参数量大、训练数据量大，才导致推理地准）**，典型应用：问答、对话、翻译、文本分类、写作、总结、代码生成等。例如：

```
第一轮输入："今天天气"
↓
Decoder ×N（N = Decoder 的层数）
↓
推理的结果："很好"或"不错"或"晴朗"，"很好"的概率最高
↓
第二轮输入："今天天气很好"
↓
Decoder ×N（N = Decoder 的层数）
↓
推理的结果："，适合"
↓
...
↓
不需要再往下推理了，最终结果："今天天气很好，适合打球"
```

优点是：

* 天然适合很长的连续生成，因为它的目标就是根据输入推理下一个 token 是什么，所以可以快速自回归地一直推理下去，直到认为不再需要推理为止

* 训练效率高，几乎可以利用互联网上的所有文本直接进行训练，因为它就是看某段文本接下来该是什么内容，也因此大可以处理各种任务、而不是只能处理翻译、摘要等特定任务

缺点是：

* 容易出现幻觉，因为它是在预测接下来的 token 最可能是什么，而不是基于理解后的正确回答，所以就可能在不知道正确与否的前提下继续编下去

代表：

* GPT
* DeepSeek
